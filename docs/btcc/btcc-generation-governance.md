# BTCC Generation Governance

## Purpose

This document defines what should stay fixed when BTCC-style pages are generated by agents, prompt systems, or Figma-assisted workflows. It complements:

- `docs/btcc/btcc-design-system.md` for visual facts and tokens.
- `docs/btcc/btcc-prompt-pack.md` for reusable prompts.
- `skills/btcc-style-generator/SKILL.md` for agent workflow.

The goal is repeatability: different generations should feel like the same product system.

## External Design-System Patterns Worth Adopting

Mature public systems commonly separate:

| Layer | What To Freeze For BTCC |
| --- | --- |
| Primitive tokens | Raw colors, gray ramps, spacing, radius, typography foundations. |
| Semantic tokens | `bg/primary`, `text/icon/primary`, `fill/Brand`, `fill/Error`, etc. |
| Component tokens | Button, input, table, tab, order book, card, modal, and navigation states. |
| Icon assets | Size, stroke style, role, naming, and fallback mapping. |
| Content rules | Terminology, labels, empty states, error language, market-data wording. |
| Accessibility | Contrast, focus, semantic state, keyboard and touch behavior. |
| Responsive behavior | Mobile, tablet, desktop trading-grid rules. |
| Generation QA | Checklist and visual inspection gates before delivery. |
| Governance | Version, source, ownership, and change log. |

## Fixed Source Of Truth Order

When sources disagree, use this priority:

1. Current user request.
2. Latest Figma source file `新BTCC APP`.
3. `btcc-design-system.md`.
4. `btcc-generation-governance.md`.
5. `btcc-prompt-pack.md`.
6. Agent judgment and fallback libraries.

If the Figma file changes materially, update the Markdown docs before relying on old assumptions.

## Token Governance

### Naming

Use these normalized names in code:

| Figma Style | Code Style |
| --- | --- |
| `text | icon/primary` | `--btcc-text-primary` |
| `text | icon/secondary` | `--btcc-text-secondary` |
| `bg/primary` | `--btcc-bg-primary` |
| `bg/model` | `--btcc-bg-modal` |
| `Divider/primary` | `--btcc-divider-primary` |
| `border/Primary` | `--btcc-border-primary` |
| `fill/Brand` | `--btcc-brand` |
| `fill/Success` | `--btcc-success` |
| `fill/Error` | `--btcc-error` |

Rules:

- Use lowercase kebab-case for CSS variables.
- Preserve the BTCC prefix: `--btcc-*`.
- Do not introduce generic names like `--primary`, `--gray-900`, or `--accent` inside BTCC-specific surfaces.
- Do not hardcode hex values inside components when a semantic token exists.

### Token Layers

Use a three-layer model:

1. Primitive: `--btcc-dark-gray-13`, `--btcc-light-gray-2`.
2. Semantic: `--btcc-bg-primary`, `--btcc-text-secondary`.
3. Component: `--btcc-button-primary-bg`, `--btcc-orderbook-bid-bg`.

Component tokens may alias semantic tokens. They should not invent new colors unless a component state is missing in the source system.

## Component-Level Fixed Rules

### Buttons

Freeze these component tokens:

| Token | Default Alias |
| --- | --- |
| `--btcc-button-primary-bg` | `--btcc-brand` |
| `--btcc-button-primary-bg-pressed` | `--btcc-brand-pressed` |
| `--btcc-button-primary-text` | `--btcc-text-on-base-button` or explicit mode token |
| `--btcc-button-long-bg` | `--btcc-success` |
| `--btcc-button-long-bg-pressed` | `--btcc-success-pressed` |
| `--btcc-button-short-bg` | `--btcc-error` |
| `--btcc-button-short-bg-pressed` | `--btcc-error-pressed` |
| `--btcc-button-disabled-bg` | `fill/Brand Button/Disable` |

Generation rule: directional trading actions must not use brand blue.

### Inputs

Freeze:

- Height: `38-44px` for trading forms.
- Background: `--btcc-fill-input`.
- Disabled background: source `fill/Page Input disable`.
- Placeholder: `--btcc-text-tertiary`.
- Border/focus: `--btcc-border-primary` plus brand focus where needed.

### Tabs

Freeze:

- Use tabs for major states.
- Active state must combine at least two cues: text weight, color, underline, border, or fill.
- Counts remain inside labels: `orders(0)`, `positions(0)`.

### Tables And Order Books

Freeze:

- Numeric columns use tabular numbers.
- Order-book rows use compact heights.
- Ask rows use error/red; bid rows use success/green.
- Depth bars are low-contrast backgrounds behind values.
- Empty tables use compact actionable empty states.

### Modals And Bottom Sheets

Freeze:

- Scrim: `bg/mask`.
- Surface: `bg/model`.
- Mobile bottom sheet includes a drag handle.
- Primary action stays visually stable.
- State summary appears before controls.

## Icon And Asset Governance

### Source Strategy

When the Figma plugin is available:

1. Search the BTCC Figma file for existing icon nodes or component instances.
2. Reuse the source icon shape where possible.
3. If implementing in code, map each icon to the nearest project icon component.
4. Use line-icon fallback only when no source equivalent is found.

### Icon Registry

Maintain this role mapping:

| Role | Source Cue | Fallback Name |
| --- | --- | --- |
| Market stats | `bar-chart-square-down` | `BarChart` |
| Chart/K-line | `k线` | `CandlestickChart` |
| More menu | `更多` | `MoreHorizontal` |
| Add funds | `plus-circle 1` | `PlusCircle` |
| Warning/info | `warning-circle` | `AlertCircle` |
| Orders/history | `file-minus-01` | `FileText` or `FileMinus` |
| Dropdown | `icon 2` / chevron vectors | `ChevronDown` |
| Deposit | deposit shortcut icon | `Wallet` or `Download` |
| Transfer | `顶部导航栏icon` | `Repeat2` or `ArrowLeftRight` |
| Demo trading | `模拟` | `BadgePlay` or `TestTube` if available |
| Bottom nav home | TabBar home | `Home` |
| Bottom nav discover | `line-chart-up-03` | `TrendingUp` |
| Bottom nav copy | TabBar copy | `Copy` |
| Bottom nav assets | `BTCCtp` / assets cue | `Wallet` |
| Bottom nav trade | TabBar trade | `ChartCandlestick` |

Rules:

- Fallback icon names are suggestions, not required if the local codebase uses another library.
- Match stroke weight and optical size before matching exact metaphor.
- Do not mix filled emoji-like icons with BTCC line icons.
- Use accessible names for icon-only buttons.

## Content Governance

### Terms To Keep Stable

Use these terms consistently:

| Concept | Preferred Label |
| --- | --- |
| Perpetual contract | `Perp` |
| Product tabs | `USDT-M`, `Coin-M`, `Spot`, `USDT-M Pro` |
| Long action | `Open Long` or `Buy/Long` depending context |
| Short action | `Open Short` or `Sell/Short` depending context |
| Take-profit / stop-loss | `TP/SL` |
| Available balance | `Available` |
| Liquidation price | `liq.price` in dense trading forms, `Liq. Price` in tables |
| Current pair | `Current Trading Pair` |
| Empty data | `No available data` |

Avoid:

- Long educational prose inside trading panels.
- Replacing standard trading terms with marketing language.
- Inconsistent casing inside the same surface.

### Empty States

Empty states should include:

1. State: what is empty.
2. Context: current pair/account when relevant.
3. Next action: deposit, transfer, demo trading, select pair, or create order.

## Responsive Governance

### Mobile

Freeze:

- 16px side gutters.
- 44px top nav rows.
- 24px toolbar icons.
- 40-44px touch targets.
- Bottom sheets for focused tasks.
- Bottom navigation only for app-like mobile screens.

### Desktop

Freeze:

- Dense trading grid.
- Chart/market panel as the largest region.
- Order book and order form as narrow operational columns.
- Orders/positions/assets panel below or beside main trading area.
- Avoid stretching mobile bottom navigation onto desktop.

### Breakpoint Behavior

| Width | Behavior |
| --- | --- |
| `< 640px` | App-like stacked layout, bottom nav allowed, bottom sheets preferred. |
| `640-1024px` | Two-column trading layout where possible; stack lower panels. |
| `> 1024px` | Multi-column trading workspace with persistent order book/form. |

## Accessibility Governance

Required:

- Focus state for all buttons, tabs, inputs, selectors, and icon-only controls.
- Accessible labels for icon-only actions.
- Non-color cue for selected and directional states.
- No clipped table values.
- No hover-only critical actions.
- Touch targets at least 40px on mobile.
- Sufficient contrast for primary and secondary text.

## Motion Governance

Use motion sparingly:

- Short transitions: `120-180ms`.
- Use motion for hover, active, sheet entrance, modal fade, tab indicator, and loading skeleton.
- Do not animate price tables aggressively unless the product requires live tick behavior.
- Loading should use neutral skeletons or shimmer, not decorative motion.

## Agent Generation Workflow

For each BTCC generation task:

1. Identify page type and target platform.
2. Read `btcc-design-system.md`.
3. Read the relevant section of `btcc-prompt-pack.md`.
4. If Figma is available, inspect the source file for tokens, icons, and matching components.
5. Choose page pattern and component grammar.
6. Generate implementation or prompt.
7. Run the BTCC QA checklist.
8. Report assumptions and any missing Figma/code assets.

## QA Checklist

Before delivery:

- Semantic tokens are used.
- Component-level tokens are not bypassed.
- Icons match BTCC size, stroke, and role conventions.
- Page type uses the correct structural pattern.
- Data density matches exchange UI.
- Directional colors are semantically correct.
- Empty/disabled/loading/selected states exist where needed.
- Desktop and mobile behavior are specified or implemented.
- No generic marketing hero unless explicitly requested.
- No decorative icon pack, arbitrary gradients, or unrelated illustration style.
